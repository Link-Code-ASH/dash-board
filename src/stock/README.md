# HUB Stock

HUB `#/stock` 탭. 별도 사이트나 서비스 가입 없이 기존 React/GitHub Pages에 포함됩니다.

- A와 Y의 입력과 계산 결과를 같은 화면에 표시합니다. 무한매수는 각각 평단가·보유 수량·추가 매수 가능 수량을 입력하며 보유 비율과 단계는 자동 계산합니다. 모바일에서는 A 다음 Y 순서로 표시합니다.
- PC에서는 시세와 계좌 패널을 읽기 편한 너비로 배치하고, 전략표는 HUB의 가용 폭을 활용합니다. 은은한 질감과 그림자로 패널·입력 영역을 구분합니다. 적용 단계의 열 전체를 A는 차분한 파랑, Y는 분홍, 두 계좌가 겹치면 보라로 표시합니다. 단계가 많아지면 전략표 안에서 가로로 스크롤합니다.
- 종목마다 무한매수 전략표는 하나이며 두 계좌에 함께 적용합니다. 단계는 가로 열, 매수·매도 기준은 세로 행입니다. 같은 표에서 편집하고 저장 전에 두 계좌의 결과를 미리 볼 수 있습니다. 저장·취소·되돌리기를 제공하며 가격 보정과 소량 보유 보정은 접힌 상세 설정에 둡니다.
- `model.js`: 8단계 IBS와 VR 계산. TQQQ 기본 규칙은 STOCK 시트를 기준으로 하며 6단계 최종 매도는 사용자 확인대로 +5%. 구간 경계는 다음 단계(40%는 2단계), 100%는 마지막 단계입니다. 소량 보유 시 매도 합계가 보유를 넘지 않도록 제한합니다. MOC 주문은 가격 대신 MOC를 표시하며 남은 수량 기준의 주문은 앞선 매도 후 잔여 수량을 사용합니다.
- 기본 종목은 TQQQ 하나입니다. 기존 SOXL은 목록에서 제외하고 `archivedAssets`에 설정을 보존합니다. 모든 계좌 입력과 기존 종목 ID는 유지됩니다.
- 개인 입력값은 `dashboard.stock` 아래에 보관하므로 기존 HUB의 계정별 저장, 병합, 백업을 따릅니다. 기존 계좌·종목 ID와 입력값을 유지하며 A/Y는 화면 표시 이름입니다. 공개 코드와 시세 JSON에는 개인 잔고가 없습니다.
- VR도 두 계좌의 현황, 매수 또는 매도 수량, 필요 입금액을 함께 표시합니다. 현금 비중 하한·상한과 적립금 투자 비율은 종목별 공통 설정으로 저장합니다. 기존 두 계좌의 설정이 다르면 처음 공통 설정을 저장할 때 A/Y 중 기준을 선택합니다. 선택 전에는 각 계좌의 기존 설정으로 계산하며 기존 입력값을 덮어쓰지 않습니다.
- VR의 외화 예수금은 **원화 환산액**을 입력합니다. 기존 시트의 현재가 대신 최근 완료된 정규장 종가를 사용합니다. 적립액은 지난주 마지막 거래일 종가를 사용합니다.

## 가격 갱신

`node scripts/stock-market.js`는 인증 없는 Yahoo Finance chart 응답에서 TQQQ, SOXL, USD/KRW를 수집해 `public/market/latest.json`에 저장합니다. 진행 중인 정규장 봉은 제외합니다. 환율은 일별 최근값으로 표시합니다. 비공식 엔드포인트이므로 제공자가 차단·변경하면 수집기 수정이 필요합니다.

개발 서버는 `/__stock-market`에서 수집(5분 캐시). GitHub Pages에서는 서버 코드를 실행할 수 없으므로 기존 배포 workflow가 UTC 평일 22:17 및 화~토 07:17에 새 스냅샷을 생성하고 배포합니다. 예약 실행은 main 반영 후 GitHub Actions 활성 상태에서 동작하며 GitHub 측 지연이 있을 수 있습니다. 데이터 수집 실패 시 배포를 중단해 기존 배포본을 유지합니다.

Stock 탭 진입/15분 간격/새로고침 버튼은 배포된 JSON을 캐시 없이 조회합니다. 가격 기준일, 수집 시각, 3일 이상 수집 지연과 실패를 표시합니다. 새로고침 버튼이 실시간 가격을 요청하는 것은 아닙니다.

현재 화면은 TQQQ의 무한매수와 VR에 집중합니다. 가격 수집 연결은 유지하며, 자동 시세 대상 확대는 `public/market/symbols.json`에서 관리합니다. 브라우저 개인 설정을 공개 수집 목록에 자동 전송하지 않습니다.

검증: `node --test tests/stock.test.js`, `npm test`, `npm run build`.
