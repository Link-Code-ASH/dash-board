# HUB Stock

HUB `#/stock` 탭. 별도 사이트나 서비스 가입 없이 기존 React/GitHub Pages에 포함됩니다.

- A와 Y의 입력과 계산 결과를 같은 화면에 표시합니다. 무한매수는 각각 평단가·보유 수량·추가 매수 가능 수량을 입력하며 보유 비율과 단계는 자동 계산합니다. 모바일에서는 A 다음 Y 순서로 표시합니다.
- 기본 화면은 계좌별 현재 입력값과 적용 단계의 매수·매도 주문만 표시합니다. 0주 주문은 생략하고 해당 주문이 없으면 별도로 표시합니다. 상단의 `전략표` 버튼 하나로 상세 창을 열며 A/Y 계좌 전환 없이 같은 표에서 규칙을 확인하고 편집합니다. 표는 창을 열 때만 불러옵니다. 저장하지 않은 변경을 버릴 때는 확인합니다. 표에는 계좌 범례나 적용 단계 색상을 표시하지 않고 매매 기준만 표시합니다.
- 전략표는 단계를 한 줄씩 세로로 놓고, 열은 단계·보유 비율(작은 막대)·매수 1~N·매도 1~N입니다. 각 칸은 평단 대비 비율(또는 `종가`)과 수량(`가능 3%`, `보유 50%`, `남은 수량 전부`, `n주`)만 크게 보이고, 가격 보정은 `1센트 낮게/높게`, 소량 보유 보정은 `1~3주면 1주` 같은 말 태그로 표시합니다. 주문 방식은 열 머리글에 한 번 쓰고 다른 칸만 태그로 표시합니다. 표 위 한 줄 범례가 평단 대비·가능·보유를 설명합니다. 주문이 없는 칸은 `–`로 비웁니다.
- 평단가 대비 + 비율은 빨강, - 비율은 파랑, 0%는 기본 글자색으로 표시합니다. 읽기와 편집, 접힌 가격 보정 값에도 같은 색 기준을 적용합니다. 매수는 모두 LOC, 매도 주문 1·2는 LOC, 주문 3은 지정가입니다. 전략표·계좌별 계산 결과·편집 미리보기에 주문 방식을 표시합니다. 기존 TQQQ 데이터와 옛 백업은 최초 로드 시 이 주문 방식으로 변환하며 8단계의 이전 MOC도 LOC로 바꿉니다. 계좌 입력·ID·가격 및 수량 비율·보정값은 유지합니다. 종목의 `orderTypesVersion: 1`로 변환 완료를 기록하므로 이후 편집한 주문 방식은 유지합니다.
- 종목별 매매 규칙과 전략표는 하나이며 두 계좌가 공유합니다. 표에는 공통 가격·수량 기준을 표시하고 계좌별 실제 주문은 기본 화면과 편집 중 A/Y 결과 미리보기에서 확인합니다. 편집 중에는 칸을 누르면 아래 고정 편집 패널에서 주문 방식·가격·수량 기준·`가격 살짝 조정(그대로/1센트 낮게/1센트 높게/직접)`·조금 보유할 때를 고칩니다. 각 줄 끝의 ✂ 버튼은 구간을 반으로 나누고(40~50% → 40~45%·45~50%, 같은 주문 복사), 합치기 버튼은 다음 단계와 하나로 합치며(이 단계의 주문 유지), ↑↓로 순서를 바꾸고 휴지통으로 지웁니다. `N단계` 이름은 순서대로 다시 매깁니다. 열 머리글의 휴지통은 그 매수·매도 칸을 지웁니다. 전략표 창은 화면 전체를 쓰고 머리글 행과 단계 열이 고정됩니다. 좁은 화면에서는 단계마다 카드로 바뀝니다. 수량 비율은 정수 퍼센트로 반올림해 표시하며 기존 규칙의 계산 정밀도는 유지합니다.
- `model.js`: 8단계 IBS와 VR 계산. TQQQ 기본 규칙은 STOCK 시트를 기준으로 하며 6단계 최종 매도는 사용자 확인대로 +5%. 구간 경계는 다음 단계(40%는 2단계), 100%는 마지막 단계입니다. 소량 보유 시 매도 합계가 보유를 넘지 않도록 제한합니다. MOC 주문은 가격 대신 MOC를 표시하며 남은 수량 기준의 주문은 앞선 매도 후 잔여 수량을 사용합니다.
- 기본 종목은 TQQQ 하나입니다. 기존 SOXL은 목록에서 제외하고 `archivedAssets`에 설정을 보존합니다. 모든 계좌 입력과 기존 종목 ID는 유지됩니다.
- 개인 입력값은 `dashboard.stock` 아래에 보관하므로 기존 HUB의 계정별 저장, 병합, 백업을 따릅니다. 기존 계좌·종목 ID와 입력값을 유지하며 A/Y는 화면 표시 이름입니다. 공개 코드와 시세 JSON에는 개인 잔고가 없습니다.
- VR은 2026.10.05 ~ 10.09를 TQQQ·현금 추가 주간으로 삼고 다음 주 비중 조정과 격주로 반복합니다. HUB의 선택 날짜를 기준으로 해당 주의 작업을 표시하고 이번 주와 다른 날짜를 보는 경우에는 '선택 주'로 구분합니다. 주말은 같은 주 월요일 기준입니다. 실제 주문이나 입금은 실행하지 않습니다.
- 현금 비중 하한·상한과 적립금 중 TQQQ 비중은 종목별 공통 설정으로 저장합니다. TQQQ 비중은 새 적립금을 주식과 현금으로 나누는 입금 계산용 값이며 전체 자산의 목표 비중과 다릅니다. 기존 두 계좌의 설정이 다르면 처음 공통 설정을 저장할 때 A/Y 중 기준을 선택합니다. 선택 전에는 각 계좌의 기존 설정으로 계산하며 기존 입력값을 덮어쓰지 않습니다.
- 비중 조정 매수의 현금 사용 한도(`cashUseLimit`)는 기본 75%입니다. 원화·원화 환산 외화 예수금의 합계에서 한도를 계산하고, 필요한 매수 수량과 한도 안에서 살 수 있는 정수 수량 중 작은 값을 제시합니다. 한도 수량은 내림하며 초과 시 '현금 한도 적용', 1주도 살 수 없으면 '매수 보류'를 표시합니다. 이 한도는 매도나 새 적립금 계산에는 적용하지 않습니다. 기존 자료에는 기본값만 적용하고 잔고·설정을 자동 교체하지 않습니다.
- VR 설정의 입금 배분은 현금 30% : TQQQ 70%로 표시하며 편집에서 어느 쪽 비율을 바꿔도 상대 비율이 합계 100%가 되도록 연결합니다. 저장 필드 `invest`는 그대로 유지합니다. 현금 포함 필요 입금액은 소수점 없는 만원 단위로 표시합니다.
- VR 보유 수량은 `vrHeld`에 별도로 입력하며 무한매수의 `held`와 독립적입니다. 평가금은 `vrHeld × 최근 완료된 정규장 종가 × USD/KRW`로 계산합니다. 새 수량을 입력하기 전까지 기존 `valuation`은 그대로 유지하고 이전 평가금으로 표시합니다. 원화 예수금·원화 환산 외화 예수금과 결과는 만원으로 표시하되 저장값은 기존 원 단위를 유지합니다. 원하는 매수 수량은 선택 메뉴와 +/- 버튼으로 조정합니다. 적립액은 지난주 마지막 거래일 종가를 사용합니다.

## 가격 갱신

`node scripts/stock-market.js`는 인증 없는 Yahoo Finance chart 응답에서 TQQQ, SOXL, USD/KRW를 수집해 `public/market/latest.json`에 저장합니다. 진행 중인 정규장 봉은 제외합니다. 환율은 일별 최근값으로 표시합니다. 비공식 엔드포인트이므로 제공자가 차단·변경하면 수집기 수정이 필요합니다.

개발 서버는 `/__stock-market`에서 수집(5분 캐시). GitHub Pages에서는 서버 코드를 실행할 수 없으므로 기존 배포 workflow가 UTC 평일 22:17 및 화~토 07:17에 새 스냅샷을 생성하고 배포합니다. 예약 실행은 main 반영 후 GitHub Actions 활성 상태에서 동작하며 GitHub 측 지연이 있을 수 있습니다. 데이터 수집 실패 시 배포를 중단해 기존 배포본을 유지합니다.

Stock 탭 진입/15분 간격/새로고침 버튼은 배포된 JSON을 캐시 없이 조회합니다. 가격 기준일, 수집 시각, 3일 이상 수집 지연과 실패를 표시합니다. 새로고침 버튼이 실시간 가격을 요청하는 것은 아닙니다.

현재 화면은 TQQQ의 무한매수와 VR에 집중합니다. 가격 수집 연결은 유지하며, 자동 시세 대상 확대는 `public/market/symbols.json`에서 관리합니다. 브라우저 개인 설정을 공개 수집 목록에 자동 전송하지 않습니다.

검증: `node --test tests/stock.test.js tests/stock-strategy.test.js`, `npm run build`.
